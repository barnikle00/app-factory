{#- ds.html — the seventeen macros. Import once: {% raw %}{% import "ds.html" as ds %}{% endraw %} WHY MACROS AND NOT CLASSES. The prior art defines 216 classes and emits ~175 of them by hand from templates. That is 175 chances per screen to type a class that does not exist, to forget the scroll container, to put two primary buttons in one block — and 216 names an agent must hold in context to write one page. Here the agent holds seventeen signatures, and the rules it must not break are encoded in those signatures rather than written down beside them: · actions() has ONE primary slot, so "at most one primary per block" is unrepresentable instead of reviewed. · table() writes its own .table-scroll, so a phone cannot scroll the page body sideways — the single most common RTL dashboard failure. · select() writes its own wrapper, because a {{ label }} {%- if hint %}{{ hint }}{% endif -%} {%- else -%}
