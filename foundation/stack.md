# Stack — one checked pick per job

The architect picks from here; a phase never adds a library on its own. Every version below was read
from its package registry when its row was added — 2026-09-15, or 2026-09-16 for the last five rows.

**None of these decide how an app looks.** The look is the project's own approved prototype, carried
into its own design layer (`design-architecture` → *Frontend source*). On the first factory app the owner compared
two generic bases — Tabler and the factory's own design system — against the app's prototype on
the same screen and chose the prototype. What belongs here is only what is the same whatever an app
looks like.

**Adding a library off this list** takes one line in the project's `ARCHITECTURE.md → Stack` saying
why the listed pick does not fit. Every library is one more thing to keep updated and one more way
to break.

**Staying on the list:** an entry whose last release is more than 18 months old says here why it is
still the pick. Recheck this file whenever a new app starts.

## Health — the same in every app (ADR 0009)

- `GET /health` — alive. Touches no dependency; answers in milliseconds.
- `GET /health/ready` — the database and every backing service, each within a time limit; `503` naming the one that failed.
- Every scheduled job writes its last success and last failure; `/health/ready` reports a job past its window.
- The container healthcheck calls `/health`.
